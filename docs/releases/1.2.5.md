# 1.2.5 — Fix login startup after first-time setup

## TL;DR

Fixes the misleading “Login item changes are disabled when VSM_HOME is set” error after a fresh installation. Update to 1.2.5, then try **Open Manager at Login** again. Your worlds and settings are preserved.

## What changed

Creating the app's normal data folder could change its URL representation by adding a trailing slash. The manager incorrectly treated that as a custom development location, even when `VSM_HOME` was not set. This could block login startup, server startup and other actions restricted in development mode during the first session.

The manager now compares normalized folder paths. Real custom data locations and explicit `VSM_HOME` overrides still keep their isolation safeguards. The development-mode error also explains the actual restriction instead of assuming an environment variable was set.

If you cannot update immediately, quit the manager, reopen it from Applications and try again. Quitting the manager leaves running servers running. If the error persists, check for an intentional custom `VSM_HOME` before changing it; removing an override does not move the worlds stored there.
